# Week 07 — Grammar-Based Parsing (BNF/BNFC)

This week replaces the ad-hoc token splitting from earlier sessions with a
proper grammar-based parser generated by **BNFC** (BNF Converter).

---

## Project layout

```
week07/
  BNF_Shell/
    bncf/           <- BNFC grammar + generated parser + shell core
      Grammar.cf    <- BNFC grammar (the source of truth)
      shell.h       <- Command struct + public API
      shell.c       <- REPL, AST evaluator, execution engine
      Makefile      <- builds both `Test` (AST printer) and `shell`
    docs/
      shell_coding.md  <- compact coding reference
    tests/
      run_tests.sh  <- automated test suite (25 tests)
```

---

## Features implemented

| Feature | Example |
|---------|---------|
| Simple command + args | `ls -l /tmp` |
| Semicolon-separated jobs | `echo a ; echo b` |
| Pipeline | `ls \| grep .c \| wc -l` |
| Output redirection | `echo hello > out.txt` |
| Input redirection | `wc -l < /etc/hostname` |
| Combined I/O redirection | `sort < in.txt > out.txt` |
| Background job | `sleep 5 &` |
| Variable assignment | `NAME=value` |
| Variable expansion | `echo $HOME` |
| Quoted strings | `echo "hello world"` |
| Built-ins: `cd`, `exit`, `export` | `cd /tmp ; export X=1` |

## Quick start

```bash
cd week07/BNF_Shell/bncf

# Install tools (Ubuntu/Debian)
sudo apt-get install -y bnfc flex bison build-essential

# Build everything (generates parser/lexer from Grammar.cf, then compiles)
make

# Debug the grammar — inspect ASTs
echo "ls -l | grep .c" | ./Test

# Run the mini-shell interactively
./shell

# Run automated tests
make test
```

## How it works

```
Grammar.cf
    |
    | bnfc --c
    v
Absyn.{c,h}   -- AST types (Input, Job, Pipeline, CommandPart, Atom, ...)
Grammar.l     -- flex lexer rules
Grammar.y     -- bison parser rules + pInput() / psInput() entry points
    |
    | flex / bison
    v
Lexer.c  Parser.c
    |
    | gcc + shell.c
    v
./shell   (REPL that parses each line and executes it)
```

`shell.c` calls `psInput(line)` for each input line, walks the resulting
AST, expands `$VAR` atoms via `getenv`, and dispatches to
`execute_pipeline` (fork + pipe + dup2 + execvp) or the built-in table.
