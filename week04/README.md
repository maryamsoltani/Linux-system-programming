# AiShell — Week 04: Command Anatomy + Package Management

A modular CLI toolkit written in C, extended with a built-in package manager.
Every command follows a standard anatomy (`cmd_spec_t`) so that metadata,
help text, and package documentation are all derived from one source of truth.

---

## Project Structure

```
week04/
├── main.c              ← dispatcher: routes argv[0] or argv[1] to a command
├── Makefile            ← builds aishell and all symlinks
├── argtable3/          ← vendored argument-parsing library
├── src/
│   ├── cmd_spec.h      ← cmd_spec_t definition + COMMAND_REGISTRY
│   ├── cmd_ls.c        ← ls command module
│   ├── cmd_cat.c       ← cat command module
│   ├── cmd_stat.c      ← stat command module
│   ├── cmd_headtail.c  ← head and tail command modules
│   ├── cmd_fileops.c   ← cp, mv, rm, mkdir, rmdir, touch
│   ├── cmd_shell.c     ← pwd, cd, env, export, unset, type
│   ├── cmd_rg.c        ← rg (regex search) command module
│   ├── cmd_edit.c      ← edit-replace-line, edit-insert-line, edit-delete-line, edit-replace
│   └── cmd_pkg.c       ← pkg (package manager) command module
└── packages/           ← generated by `pkg build` (not committed)
    └── <name>/
        ├── pkg.json    ← package metadata
        └── usage.txt   ← help text
```

## How to Build

```bash
make
```

Creates the `aishell` binary. To also create per-command symlinks:

```bash
make symlinks
```

This lets you call commands directly (e.g. `./ls`, `./cat`) instead of
`./aishell ls`, `./aishell cat`.

To clean everything including generated packages:

```bash
make clean
```

> **Note:** Always run `make clean && make` after editing `src/cmd_spec.h`,
> since the Makefile does not track header dependencies automatically.

## Command Anatomy

Every command in this project follows the same standard structure defined in
[src/cmd_spec.h](src/cmd_spec.h):

```c
typedef struct cmd_spec {
    const char *name;        // CLI name: "ls", "cat", "pkg", ...
    const char *summary;     // one-line description (used in --list and pkg metadata)
    const char *long_help;   // longer description (may be NULL)
    const char *category;    // group: "filesystem", "shell", "search", "edit", "package"
    int  (*run)(int argc, char **argv);   // entry point
    void (*print_usage)(FILE *out);       // help text printer
} cmd_spec_t;
```

Each command module provides exactly one `cmd_spec_t` and uses `argtable3`
for all argument parsing and help output. Adding a new command means:

1. Write `src/cmd_<name>.c` with `<name>_run()`, `<name>_print_usage()`, and `spec_<name>`.
2. Add `extern cmd_spec_t spec_<name>;` and `&spec_<name>` to `src/cmd_spec.h`.
3. Add `src/cmd_<name>.c` to `CMD_SRC` in `Makefile`.

## Available Commands

### Filesystem

| Command | Description |
|---|---|
| `ls` | List directory contents (`-l`, `-a`, `--json`) |
| `cat` | Concatenate and print files (`-n`, `--json`) |
| `stat` | Display file/inode metadata (`--json`) |
| `head` | Print first N lines of a file |
| `tail` | Print last N lines of a file |
| `cp` | Copy files or directories |
| `mv` | Move or rename files |
| `rm` | Remove files or directories |
| `mkdir` | Create directories |
| `rmdir` | Remove empty directories |
| `touch` | Create file or update timestamp |

### Shell / Environment

| Command | Description |
|---|---|
| `pwd` | Print working directory |
| `cd` | Change working directory |
| `env` | List environment variables |
| `export` | Set an environment variable |
| `unset` | Unset an environment variable |
| `type` | Show how a command name is resolved |
| `echo` | Print text to standard output (`-n`, `--json`) |
| `hello` | Print a greeting message (`-n`, `--json`) |

### Search

| Command | Description |
|---|---|
| `rg` | Search file contents with regex (`--json`, `--fixed-strings`) |

### Structured Editing

| Command | Description |
|---|---|
| `edit-replace-line` | Replace a single line in a file by line number |
| `edit-insert-line` | Insert a line before a given line number |
| `edit-delete-line` | Delete a single line from a file |
| `edit-replace` | Global find/replace with regex across a file (`--json`) |

| Command | Description |
|---|---|
| `pkg` | Full package manager — install, remove, build, pack, and pip |

Every command accepts `-h` / `--help` for usage information.

## Package Manager (`pkg`)

The `pkg` command treats each `cmd_spec_t` module as a package. It derives
all metadata and documentation directly from the command's struct — no
separate package manifest to maintain.

### Subcommands

#### `pkg list`
List all registered commands with their install status.

```bash
./aishell pkg list
```

#### `pkg build [name]`
Generate `packages/<name>/pkg.json` and `packages/<name>/usage.txt`.

```bash
./aishell pkg build          # build all packages
./aishell pkg build hello    # build only the hello package
```

**`pkg.json`** — metadata from `cmd_spec_t`:
```json
{
  "name": "hello",
  "version": "1.0.0",
  "category": "shell",
  "summary": "Print a greeting message",
  "description": "..."
}
```

#### `pkg pack [name]`
Bundle a built package into a `.tar.gz` archive.

```bash
./aishell pkg pack hello     # → packages/hello.tar.gz
./aishell pkg pack           # pack all
```

#### `pkg install <name|file.tar.gz>`
Install a command to `~/.local/bin` as a symlink to `aishell`.

```bash
./aishell pkg install hello
./aishell pkg install packages/hello.tar.gz
```

After installing, add `~/.local/bin` to your PATH:
```bash
export PATH="$HOME/.local/bin:$PATH"
```

#### `pkg remove <name>`
Uninstall a previously installed command.

```bash
./aishell pkg remove hello
```

#### `pkg installed`
List all installed packages and their paths.

```bash
./aishell pkg installed
```

#### `pkg version <name>`
Show the version of a package from its `cmd_spec_t`.

```bash
./aishell pkg version hello    # → hello 1.0.0
```

#### `pkg pip <subcmd> [args...]`
Run pip to install Python packages.

```bash
./aishell pkg pip install requests
./aishell pkg pip list
./aishell pkg pip uninstall requests
```

#### `pkg info <name>`
Show full details for one package.

```bash
./aishell pkg info hello
```

### Package smoke test

```bash
make pkg-test
```

Runs `pkg list`, `pkg build` (all), and `pkg info ls` in sequence.

## Design Notes

**Single source of truth**: the `cmd_spec_t` struct is the only place where a
command's name, description, and help text are defined. The dispatcher, the
`--list` output, and the package manager all read from the same struct —
there is nothing to keep in sync.

**Agent-ready output**: commands that produce structured data support
`--json` so that AI agents and scripts can consume their output without
parsing human-readable text.

**Symlink dispatch**: `main()` checks `argv[0]`. If it equals `"aishell"`,
the next argument is the command name. Otherwise, the binary is assumed to
have been invoked via a symlink named after the command. This means each
command can also be installed as a standalone binary.
